## 实现：卡拉OK逐词高亮字幕（仿雪球双语插件效果）

需求来源：用户提供了雪球双语 Chrome 插件（ID nbeghbnelcdncbbgniiokocdinabgofp），逆向分析其"逐词高亮"实现后，要求在 NouTube 里实现同样效果。用户选择：**原文逐词高亮（不翻译）+ 设置开关**。

### 逆向分析结论（详见 .karaoke_analysis/）
- 雪球插件核心在 content.fda02ec3.js 的 `~/subtitle/Renderer` 模块（Parcel `1E1Tx`）
- 关键函数：`updateSubtitlesByTime`(eq)、`renderLiveLine`(eR)、`eL`(渲染核心)、`eI`(生成高亮span)、`findWordsInRange`
- 原理：词级时间戳 + video.currentTime 每帧匹配 + 重绘 span + CSS transition；无空格语言用 Intl.Segmenter 按字符插值
- 词时间戳来源：YouTube json3 字幕 seg 的 `tOffsetMs`（相对行开始的偏移）

### NouTube 架构要点
- React Native/Expo + WebView 加载 YouTube；content script（content/main.ts）打包成 assets/scripts/main.bjs 注入
- 应用本身不抓字幕，字幕由 YouTube 原生 DOM 渲染；词级时间戳解析原本不存在
- 设置真源 states/settings.ts（4处：接口/normalize/snapshot/defaults）；下发链路 MainPageContent.tsx + extension/lib/{state,content-settings}.ts
- 设置变更靠 MainPageContent 里逐个 useObserveEffect(settings$.X) 订阅后 syncSettingsToWebview
- CSS 统一注入到 `<style id="_nou_injected_css">`（content/css.ts 的 getInjectedCss/getCoreCss）

### 实现方案（自绘字幕层，因为原生 DOM 无稳定逐词结构）
- 新增 `lib/karaoke.ts`：纯解析库，json3 → 带词时间的行；字段名是 `utf8` + `tOffsetMs`（**不是** utf8String/tStartMs-per-seg！首词 offset 常省略=0）；无 offset 时按字符数插值兜底

## 深夜迭代 v4：修复「均匀变色」+ 字体/颜色/拖动（用户反馈）

用户反馈：能看到 karaoke 效果了，但**变色和发音不对齐，是均匀变的**；并要求字幕设置加字体/颜色、字幕可上下拖动、点词查词。

### 根因（重要）
- `pickTrack` 原先取 `usable[0]` —— YouTube `captionTracks` 里**人工上传字幕排在最前**，而人工字幕的 json3 一条 event 只有一个整行 seg，**没有逐词 `tOffsetMs`** → `parseJson3` 退化成 `interpolateWordTimes`（按字符数均分整行时长）→ 匀速扫描
- 另外 DOM 兜底用 `text.length * 0.075` 拍脑袋估时长，节奏必然不对
- 真正带逐词时间戳的是 **`kind: 'asr'` 自动字幕轨道**的 json3/srv3

### 修复
- `rankTracks()`：**ASR 轨道优先**，translated/forced 降级；`loadSubtitles` 并行发起小批量候选（ASR json3+srv3、后续轨道 json3、vtt），`Promise.allSettled` 后**优先选 `timed===true` 的结果**，最坏延迟只有一个 timeout
- `lib/karaoke.ts`：`KaraokeLine` 加 `timed?`；`parseJson3` 的 `hasWordTiming` 收紧为「≥2 个不同 offset」（单个 `tOffsetMs:0` 不算）；定时段若含多词则用 `speechWeightedWordTimes` 展开；新增 `speechWeightedWordTimes`（音节/词长/CJK/标点停顿加权，非匀速）、`lineFromObservedWords`（从 DOM 观察的真实出现时间构造行）、`lineFromText`/`parseVtt`/`parseSrv3` 全改加权并标 timed
- **DOM 逐词观察**：`observeNativeWords()` 监听 `.ytp-caption-segment` 文本增长，每个新词记录 `video.currentTime` 作为真实发音时间；整行一次出现（人工字幕）才回退加权插值，并用上一行实测时长。CSS 从 `display:none` 改为 **`opacity:0`** 隐藏原生字幕 —— 必须保留在渲染树里，YouTube 才会继续更新文本（这正是时序源）
- `renderFrame(..., keepHidden)`：有 caption payload 时句间空隙保持隐藏，避免原生字幕闪回
- 单测 15/15 通过

### 新增设置（四类字段，全链路同步）

- **拖动定位**：容器 `pointerdown/move/up` + `setPointerCapture`，阈值 4px 区分点击与拖动；拖动即时改 CSS 变量，松手 `emit('subtitle-position', {value})` → RN `settings$.interactiveSubtitlePosition.set()` 持久化；`suppressClickUntil` 防止拖动误触查词

### 「看不到」的排查结论
- 设置**确实存在**且在 APK bundle 内，但位于 `SettingsModalTabSettings.tsx` 的 `SettingsYouTubeContent` → `settings.preferencesPlayback` 分组**最底部**（第 925-936 行），前面十几个开关，路径为「设置 → YouTube → 播放 → 一直往下滚」，与截图的画面内工具栏形态完全不同
- **点词没反应的真 bug**：`onPointerDown` 对容器调用 `setPointerCapture()`，会把后续 click 的 target 改写成容器本身，`onWordClick` 里 `.closest('.nou-sub-word')` 永远返回 null → 点击完全无响应。修法：去掉 setPointerCapture，把 `pointermove/up/cancel` 改绑 `window`（拖动移出字幕仍有效）
- 隐藏的原生字幕 CSS 已有 `pointer-events:none`，不是点击拦截原因

### 实现（全部在 content 层，无 native 通信改动）
- 新增 `content/subtitle-toolbar.ts`：常驻工具栏 + 4 个弹出面板（语言显示/字体大小/主题样式/设置）、设置持久化到 `localStorage['nou:subtitleToolbar']`、`getToolbarSettings()/onToolbarChange()/setToolbarEnabled()/showWordCard()/hideWordCard()`；中文/英文按 `settings.language` 自动切换；折叠后留 ⚙ 恢复按钮，避免用户把自己锁死
